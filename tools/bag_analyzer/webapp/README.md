# F1TENTH Bag Analyzer — 웹앱 (무터미널)

브라우저에 rosbag을 드래그하면 **3D 리플레이 + 주행 그래프 + 자동 튜닝 가이드**까지
전부 클라이언트에서 처리한다. **ROS·터미널·설치 불필요.** 파일은 서버로 안 올라가고
브라우저 안에서만 파싱된다(sql.js WASM + 자체 CDR/MCAP 파서).

## 지원 형식 — `.db3`(sqlite3) / `.mcap` 둘 다 (2026-08-04)
jazzy의 rosbag2 **기본 저장 형식이 mcap**이라 `--storage sqlite3` 없이 기록하면 `.mcap`이
나온다. 예전엔 그때마다 `ros2 bag convert`가 필요했는데, 이제 웹앱이 둘 다 직접 읽는다.
파일 확장자가 아니라 **매직 바이트로 판별**하므로 이름이 어떻든 상관없고, 분할 bag에서 두
형식이 섞여 있어도 파일별로 알아서 처리한다.

- ⚠️ **압축된 mcap 청크(lz4/zstd)는 미지원** — rosbag2 기본이 무압축이라 실사용엔 문제없다.
  압축 bag이면 조용히 빈 결과를 내지 않고 압축 방식을 짚어 에러를 띄운다.
- ℹ️ CLI 도구(`../analyze_bag.py`)는 아직 `.db3` 전용이다(sqlite3로 직접 읽는 구조).
  CLI로 mcap을 보려면 `ros2 bag convert`가 여전히 필요하다.

## 쓰는 법 — 두 가지
1. **로컬 파일 (가장 확실):** `webapp.html`을 더블클릭 → 브라우저 열림 → bag 폴더 드래그. 끝.
2. **URL 공유:** claude.ai 아티팩트로 게시된 링크를 팀원에게. (아티팩트 CSP가 WASM을 막으면
   1번 또는 자체 호스팅으로. GitHub Pages 등에 `webapp.html` 올리면 영구 팀 URL이 된다.)

## 파일
- `app.html` — 앱 본체(CSS/HTML/JS). sql.js는 토큰(`__WASM_B64__`, `/*__SQLJS_GLUE__*/`)으로 주입.
- `vendor/sql-wasm.js`, `vendor/sql-wasm.wasm` — 벤더링된 sql.js 1.10.3 (SQLite WASM).
- `build.py` — 조립: `app.html` + vendor → `webapp.html`(독립형) + `webapp.fragment.html`(아티팩트용).

## 빌드 (앱 수정 시에만)
```bash
python3 build.py     # → webapp.html, webapp.fragment.html
```

## 코너 통과 속도 (2026-08-01 추가)
"코너를 몇으로 도나"는 상단 **속도 범위**로는 절대 안 나온다 — 생 최저속은 정지출발이
지배해 항상 0이다. 그래서 코너 구간(κ>0.15 = 반경 6.7 m 미만)마다 따로 낸다:

- KPI 타일 **코너 최저속** — 에이펙스 최저~최대 + 중앙값 + 가장 느린 코너 시각
- 표 **코너별 통과 속도** — 랩 / 진입 / **에이펙스(최저)** / 탈출 / 최소반경 / 피크 a_lat /
  설정상 가능 √(MLA·R) / 판정. `◀` = 최저 에이펙스 코너
- 속도 그래프에 코너 구간 음영 + 에이펙스 점(빨강 = 설정 초과)

### 🔴 판정 기준을 실그립 → 설정 `max_lateral_accel`로 바꿨다 (2026-08-05)

**바뀐 것**: 코너 판정·차트 레드라인·궤적 빨강점의 기준이 전부 **그 주행에 실제로 넣은
`max_lateral_accel`**이 됐다. 값은 bag에 안 실리므로(`/parameter_events` 미녹화) 코너 표
오른쪽 위 입력칸에 직접 넣는다(기본 6.0 = 런치 기본값, localStorage에 남아 다음 bag에도 이어짐).
바꾸면 표·차트·궤적이 즉시 다시 그려진다.

**왜**: 전엔 `GRIP_ASSUMED = 6.5`라는 **하드코딩 가정값**이 기준이었다. 실그립은 bag에서
제어상실을 관측해야만 잴 수 있는데, 안 밀어붙인 주행에선 원리적으로 못 정하므로 그때마다
6.5로 폴백했다. 08-04 세미슬릭 교체로 이 가정이 낡자 08-05 `run_0805_160913`(23랩, 사고 0,
조향 최대 0.3887 < 0.410)에서 **49코너 중 48개가 "그립 초과"**로 떴다. 타이어는 멀쩡했고
가정값만 틀린 것이다.

**두 질문을 분리한다**:

| | 무엇을 답하나 | 어디서 오나 |
|---|---|---|
| **설정 MLA** | 컨트롤러가 지키라고 한 값을 지켰나 = **사전감속 성능** | 사용자 입력 |
| **실그립** | 타이어가 버텼나 | bag 실측 — **제어상실이 관측된 bag에서만** |

그래서 "설정 초과"는 미끄러짐이 아니다. 짧고 급한 코너에서 제동거리가 모자라 목표 속도에
못 내려간 것이 보통이고, 실그립이 실측된 bag에서만 "실제로 밀린 코너"로 격상된다(심각도도
`주의` → `치명`으로 올라간다).

**새 진단 — "설정을 올릴 근거가 있다"**: 제어상실 없음 + 조향 미포화 + 설정을 10% 넘게
넘겨 돌았음 + **고하중에서 요레이트 추종률이 안 무너짐**, 넷이 다 서면 `max_lateral_accel`
상향을 권고한다. 마지막 조건이 핵심이다 — 타이어가 포화하면 하중이 커질수록 지시 대비 실측
요레이트가 급락하는데, 평평하면 아직 선형 영역이다. 위 bag 실측: a_lat < 3.6에서 **88%**,
> 6.0에서 **101%** → 권고 `max_lateral_accel:=8.2`.

⚠️ 반대로 `max_speed` **하향** 권고는 이제 실그립을 실제로 넘은 bag에서만 나온다. 낡은
설정값 하나로 랩타임을 깎아버리던 경로를 막은 것이다.

⚠️ 코너 표·차트는 입력 즉시 갱신되지만 **'파트별 가이드'의 진단은 bag을 열 때의 값으로
굳어 있다**(재계산하려면 bag 재파싱). 값을 바꾸면 그 섹션에 경고 배지가 뜬다.

⚠️ 에이펙스는 코너 구간 판정에 걸린 표본이 아니라 **i0~i1 전 구간**에서 찾는다. 판정 조건에
`v>1.0`이 있어서, 걸린 표본만 보면 1 m/s 아래로 떨어지는 진짜 에이펙스가 통째로 빠진다.

## 🔵 플롯 탭 — 임의 토픽·필드 시계열 (2026-08-07 신설)

PlotJuggler를 대신하는 기능. **bag이 스키마를 자체 포함**하므로(db3는 `message_definitions`
테이블, mcap은 Schema 레코드에 `.msg` 원문) ROS 설치 없이 브라우저 안에서 **아무 토픽이나**
디코드해 그린다. 손으로 짠 파서(`pOdom`·`pImu`…)가 아는 토픽에만 묶여 있던 제약이 사라졌다.

- 왼쪽 트리에서 토픽을 펼쳐 필드를 클릭 → **마지막 플롯**에 시리즈 추가
- **+ 플롯 추가**로 창을 나누면 **시간축과 재생 커서가 다른 모든 그래프와 동기**된다
  (기존 `drawChart`를 그대로 쓰기 때문)
- 배열 필드는 `[i]`를 눌러 인덱스를 지정해야 뽑힌다 — `/scan`(1081개 × 1588 메시지)을
  통째로 펼치면 브라우저가 죽으므로 **지연 파싱**이 기본이다
- **CSV 내보내기**: 모든 시리즈를 공통 시간축(합집합 + zero-order hold)으로 합쳐 저장

⚠️ 원시 CDR 보관 총량 상한 **180 MB**. 넘으면 그 시점부터 보관을 멈추고 해설에 경고를 띄운다
(조용히 잘리지 않게).
⚠️ 구 rosbag2로 기록돼 `message_definitions`가 없는 bag은 그 토픽의 필드 목록이 비어 보인다.

## 🔵 코너 통과 속도 — 맵 고정 검출로 교체 (2026-08-07)

**구 방식**: 주행 궤적의 κ=wz/v로 코너를 잘랐다. 실측 요레이트 기반이라 랩마다 경계가
흔들리고 같은 물리 코너가 랩에 따라 다른 구간으로 잡혀, "진입·에이펙스·탈출이 정확히
어디냐"가 불명확했다.

**새 방식**: `/global_waypoints`의 `kappa_radpm`으로 코너를 정의한다 — 랩과 무관하게 고정이라
매 랩 **정확히 같은 지점**에서 속도를 읽는다. 경로가 없는 bag은 구 방식으로 자동 폴백한다.

- 진입/탈출 = |κ|가 `CORNER_KTHR`(0.15)을 넘고/떨어지는 경로 지점
- 에이펙스 = 그 구간의 곡률 최대점(**기하** 에이펙스, 랩마다 동일)
- **최저** = 구간 안에서 실제로 낸 최저속, **에이펙스 오차** = 그 지점이 기하 에이펙스보다
  몇 웨이포인트 늦었나(+)/일렀나(−) → 브레이킹 포인트가 늦은지 이른지가 바로 보인다
- 반경 R은 경로 기하값이라 랩마다 같다(구 `minRad`는 주행 요레이트라 흔들렸다)
- 표는 **턴 → 랩** 순으로 묶어 같은 코너를 세로로 비교한다
- 맵에는 코너 **구간 전체**를 굵게 덧그리고 양 끝에 진입/탈출 사각형 마커를 찍는다

🔑 **더블 에이펙스 분리**(`CORNER_SPLIT`=0.65): 봉우리 사이 골이 작은 쪽 봉우리의 65% 미만이면
두 코너로 쪼갠다. 0807 트랙에서 κ 0.646·0.533 두 봉우리 사이 골 0.338이 임계(0.15) 위라
안 끊겨 **8m짜리 한 코너**로 잡혀 있었다 — 이걸 T2/T3로 분리했다(총 3개 → 4개 코너).

## ❌ 파트별 튜닝 가이드 제거 (2026-08-07)
사용자 요청으로 섹션·`renderReport`의 가이드 렌더링·`D.findings`/`D.rec`를 제거했다.
⚠️ `diagnose()` 안의 `F(...)` 호출부는 **if/else 체인을 보존하려고 남겨 두고 `F`를 no-op으로**
바꿨다(호출부만 지우면 `if(a)F(..); else if(b)F(..);`가 깨진다). 되살리려면 `F`를 원래
`findings.push(...)`로 되돌리고 반환값에 `findings`를 추가하면 된다.
