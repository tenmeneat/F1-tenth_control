# F1TENTH Bag Analyzer — 웹앱 (무터미널)

브라우저에 rosbag을 드래그하면 **3D 리플레이 + 주행 그래프 + 자동 튜닝 가이드**까지
전부 클라이언트에서 처리한다. **ROS·터미널·설치 불필요.** 파일은 서버로 안 올라가고
브라우저 안에서만 파싱된다(sql.js WASM + 자체 CDR/MCAP 파서).

## 지원 형식 — `.db3`(sqlite3) / `.mcap` 둘 다 (2026-08-04)
jazzy의 rosbag2 **기본 저장 형식이 mcap**이라 `--storage sqlite3` 없이 기록하면 `.mcap`이
나온다. 예전엔 그때마다 `ros2 bag convert`가 필요했는데, 이제 웹앱이 둘 다 직접 읽는다.
파일 확장자가 아니라 **매직 바이트로 판별**하므로 이름이 어떻든 상관없고, 분할 bag에서 두
형식이 섞여 있어도 파일별로 알아서 처리한다.

- ⚠️ **압축된 mcap 청크(lz4/zstd)는 미지원** — rosbag2 기본이 무압축이라 실사용엔 문제없다.
  압축 bag이면 조용히 빈 결과를 내지 않고 압축 방식을 짚어 에러를 띄운다.
- ℹ️ CLI 도구(`../analyze_bag.py`)는 아직 `.db3` 전용이다(sqlite3로 직접 읽는 구조).
  CLI로 mcap을 보려면 `ros2 bag convert`가 여전히 필요하다.

## 쓰는 법 — 두 가지
1. **로컬 파일 (가장 확실):** `webapp.html`을 더블클릭 → 브라우저 열림 → bag 폴더 드래그. 끝.
2. **URL 공유:** claude.ai 아티팩트로 게시된 링크를 팀원에게. (아티팩트 CSP가 WASM을 막으면
   1번 또는 자체 호스팅으로. GitHub Pages 등에 `webapp.html` 올리면 영구 팀 URL이 된다.)

## 파일
- `app.html` — 앱 본체(CSS/HTML/JS). sql.js는 토큰(`__WASM_B64__`, `/*__SQLJS_GLUE__*/`)으로 주입.
- `vendor/sql-wasm.js`, `vendor/sql-wasm.wasm` — 벤더링된 sql.js 1.10.3 (SQLite WASM).
- `build.py` — 조립: `app.html` + vendor → `webapp.html`(독립형) + `webapp.fragment.html`(아티팩트용).

## 빌드 (앱 수정 시에만)
```bash
python3 build.py     # → webapp.html, webapp.fragment.html
```

## 코너 · 섹터 탐색기 (2026-08-15 개편)

"코너를 몇으로 도나"는 상단 **속도 범위**로는 절대 안 나온다 — 생 최저속은 정지출발이
지배해 항상 0이다. 그래서 코너 구간(글로벌 경로의 |κ|>0.15 = 반경 6.7 m 미만)마다 따로 낸다.

### 🔴 두 표를 하나의 탐색기로 합쳤다

**구 구성**: `코너별 통과 속도`(랩×턴 세로 표)와 `섹터별 벽 여유`(가로 스크롤 표) 두 섹션이
따로 있었다. 둘은 **같은 구간의 다른 면**인데 화면이 갈라져 있어서, "이 코너를 열어도 되나"에
답하려면 두 표를 s 구간으로 눈짐작 매칭해야 했고 어느 쪽도 한 화면에 안 들어왔다.

**새 구성**: 맵이 주인공이고, 구간을 클릭하면 맵이 왼쪽으로 밀리며(0.42 s 트랜지션) 그 구간의
모든 지표가 오른쪽 패널에 펼쳐진다.

- **맵** — 코너는 T번호 색, 직선은 회색. 마커의 링 색이 그 구간 판정이라 맵만 봐도 어디가
  막혔는지 보인다. 클릭 = 상세 열기 / 빈 곳 클릭 = 닫기
- **상세 패널** — 헤더(R·방향·s 구간·통과 횟수) → 판정 배너(+사유) → 지표 타일 →
  **랩별 기록 표** → 한 줄 결론. `←`/`→`로 다음 구간
- **랩별 기록 표가 통합의 핵심**이다: 한 줄에 그 랩의 진입/에이펙스/최저/브레이킹 오차/탈출/
  피크 a_lat/**접지**/**벽 여유 p5**/판정이 다 있다 — 속도와 벽 여유를 눈으로 이을 필요가 없다
- **아래 개요 표** — 한 줄 = 한 섹터(색인). 클릭하면 상세가 열리고 마우스를 올리면 맵에서 켜진다
- 직선은 속도·벽 여유만 보여준다(그립 캡이 비활성이라 `max_lateral_accel`을 올려도 이득 0)

### 🔴 판정: "설정 초과"와 "미끄러짐"을 분리했다 (2026-08-15)

구 판정은 `peak |a_lat| > 설정 MLA`면 무조건 빨간 **"설정 초과 N×"**였다. 실차에서 안 미끄러진
주행이 사고처럼 보였다. 미끄러짐의 증거는 a_lat 크기가 아니다:

| 판정 | 조건 | 뜻 |
|---|---|---|
| 🔴 **조향 포화** | 선회반경이 최소 선회반경의 1.2배 아래 | 풀락에 붙어 더 못 꺾음 |
| 🔴 **언더스티어 N%** | 요레이트 추종률 < 78% | 명령만큼 안 돌아감 |
| 🔴 **미끄러짐 N×** | 실측 그립 초과 **이면서** 요레이트 추종률 < 90% | 진짜 밀림 |
| 🟠 **감속 미달 N×** | a_lat이 설정 MLA를 15% 초과, 접지는 정상 | 타이어가 아니라 **사전감속** 문제 |
| 🔵 **여유 −N%** | 최저속이 √(MLA·R)의 85% 미만 | 랩타임 여유가 여기 |
| 🟢 적정 | 그 외 | |

🔑 **접지 = 요레이트 추종률**(실측 wz / 명령 wz, 코너 구간 중앙값, 명령 wz > 0.8 rad/s 표본만).
표에 열로 노출한다 — 100%면 "차가 명령대로 돌았다 = 안 미끄러졌다"는 **직접 증거**다.

⚠️ **"실측 그립 초과"만으로 미끄러졌다고 하면 안 된다.** `estimateGrip`의 실그립은 onset 직전
a_lat의 p95라, 노이즈 한 샘플이 물리 상한(11 m/s²)을 스치기만 해도 `reached=true`가 되고 그
뒤로는 "정상 주행의 p95"가 그립으로 굳는다. 0814 bag이 정확히 그랬다 — 요레이트 추종률이 전
코너 100%(min 0.992 / max 1.018)인데 36코너 중 25개가 "미끄러짐"으로 떴다. 그래서 교차검증한다.

⚠️ 15% 임계의 근거: peak a_lat은 **순간 최대 샘플**이고 MLA는 설계 상한이며, 기하 반경 R과
실제 주행 반경도 다르다. 1.0으로 자르면 정상 주행이 상시 주황이 된다.

### 🔴 결승선을 넘는 코너가 랩 전체로 뭉개지던 버그 (2026-08-15 수정)

`measureMapCorners`가 **랩 구간마다** i0/iA/i1에 가장 가까운 샘플을 각각 따로 찾고 그 min~max를
코너로 삼았다. s0 > s1인 코너(결승선을 넘는 코너)에서는 진입이 랩 끝, 탈출이 랩 처음에 잡혀
**랩 전체가 한 코너**가 됐다 — 0814 T5(실제 9.8 m)가 390샘플·7.8 s = 랩의 82%로 잡히고
소요시간이 음수(−6.9 s)였으며, peak |a_lat|이 그 랩 최대치라 판정이 통째로 거짓이었다.

→ 랩으로 자르지 않고 **진입 → 에이펙스 → 탈출을 순서대로** 통과하는 것을 상태기계로 찾는다.
랩 경계를 넘는 코너도 한 번의 통과로 잡히고, 랩 번호는 에이펙스 시각으로 붙인다.
수정 후 T5는 130샘플·2.6 s로 정상화됐고 랩당 코너가 정확히 5개씩 잡힌다.

- ⚠️ 짧은 코너는 **허용 오차를 코너 길이에 맞춰 줄여야** 한다. 0814 T4는 3 웨이포인트(0.75 m)라
  고정 TOL(3)에서는 진입·에이펙스·탈출 판정창이 통째로 겹쳐 제자리에서 계속 재발화한다 —
  한 랩에 2샘플짜리 가짜 통과가 5개씩 찍혔다. `tol = min(TOL, span/2)` + 통과 후 코너를
  충분히 벗어나야 재무장(re-arm).

### 판정 기준은 실그립이 아니라 설정 `max_lateral_accel`이다 (2026-08-05)

값은 bag에 안 실리므로(`/parameter_events` 미녹화) 섹션 오른쪽 위 입력칸에 직접 넣는다
(기본 6.0, localStorage에 남아 다음 bag에도 이어짐). 바꾸면 표·상세·맵이 즉시 다시 그려진다.

**두 질문을 분리한다**:

| | 무엇을 답하나 | 어디서 오나 |
|---|---|---|
| **설정 MLA** | 컨트롤러가 지키라고 한 값을 지켰나 = **사전감속 성능** | 사용자 입력 |
| **실그립** | 타이어가 버텼나 | bag 실측 — 제어상실이 관측된 bag에서만, 그리고 요레이트 추종률로 교차검증 |

⚠️ 에이펙스는 코너 구간 판정에 걸린 표본이 아니라 **i0~i1 전 구간**에서 찾는다. 판정 조건에
`v>1.0`이 있어서, 걸린 표본만 보면 1 m/s 아래로 떨어지는 진짜 에이펙스가 통째로 빠진다.

### 벽 여유 (`/scan` 실측) — 탐색기에 흡수됨

섹터별 벽 여유·실측 그립·추종오차로 "이 코너의 `max_lateral_accel`을 올려도 되나"를 판정한다.
기준: 여유 p5 ≥ 0.20 · min ≥ 0.12 · 횡오차 p95 ≤ 0.35 · 랩 추세 ≥ −1 cm/랩 (0807 전복이 실측
여유 0.117 m에서 접촉했고 직전 랩들이 이미 깎이고 있던 데서 잡은 값).

⚠️ 벽 여유는 **차의 실제 위치** 기준이라 라인 품질이 아니라 "지금 안 부딪히는가"를 잰다.
트랙에 장애물이 있으면 `/scan`은 그걸 벽으로 본다 — 클린 랩 bag으로 잴 것.
⚠️ 플래너의 `d_left`/`d_right`로 판정하지 말 것(0807 실측 0.16~0.23 m 낙관적).

`섹터 YAML 내려받기`로 `sectors.yaml` 초안을 얻는다(다운로드가 막히는 아티팩트 샌드박스에서도
화면에 항상 뿌린다). 🟢 섹터의 `scale`만 **한 번에 하나씩 +0.1** 올리고 매번 재측정할 것.

## 🔵 코너 통과 속도 — 맵 고정 검출로 교체 (2026-08-07)

**구 방식**: 주행 궤적의 κ=wz/v로 코너를 잘랐다. 실측 요레이트 기반이라 랩마다 경계가
흔들리고 같은 물리 코너가 랩에 따라 다른 구간으로 잡혀, "진입·에이펙스·탈출이 정확히
어디냐"가 불명확했다.

**새 방식**: `/global_waypoints`의 `kappa_radpm`으로 코너를 정의한다 — 랩과 무관하게 고정이라
매 랩 **정확히 같은 지점**에서 속도를 읽는다. 경로가 없는 bag은 구 방식으로 자동 폴백한다.

- 진입/탈출 = |κ|가 `CORNER_KTHR`(0.15)을 넘고/떨어지는 경로 지점
- 에이펙스 = 그 구간의 곡률 최대점(**기하** 에이펙스, 랩마다 동일)
- **최저** = 구간 안에서 실제로 낸 최저속, **에이펙스 오차** = 그 지점이 기하 에이펙스보다
  몇 웨이포인트 늦었나(+)/일렀나(−) → 브레이킹 포인트가 늦은지 이른지가 바로 보인다
- 반경 R은 경로 기하값이라 랩마다 같다(구 `minRad`는 주행 요레이트라 흔들렸다)
- 맵에는 코너 **구간 전체**를 굵게 덧그린다(선택하면 양 끝에 사각형 마커)
